Appendix — solver settings, repeats and core counts

This is the material the poster refers to. Every figure on the sheet is generated from measured batch-solver output; no value is typed by hand.

Discretisation and solver

Mesh77,928 finite elements; 4.167 mm along the tape
Relative tolerance1×10−4
Time integrationBDF, maximum order 2, damping factor 0.15
Output interval0.2 ms
Conductor layersCu 20 / Ag 2 / Hastelloy 50 / REBCO 1 / Ag 2 / Cu 20 µm (95 µm total)
Coolingtemperature-dependent LN2 boiling curve on 104 exterior solid faces, not a constant film coefficient

Time windows

Main result0–20 ms in one unsegmented window: 10 ms energising, then 10 ms faulted
Clearing-time scansix discrete breaker settings, one run each; the longest runs to 110 ms in eleven 10 ms segments

Repeats

The solver is not bit-reproducible across runs, so the electrical result was repeated. Three repeats of the production case agree to every printed digit of the limited current peak. A dedicated repeat study of the temperature scatter is still in progress; until it closes, no temperature difference below 0.01 K on this model line is claimed to be resolvable, and no error bar is quoted on any temperature.

Core counts

Every production leg runs on 17 cores. This is measured, not assumed: raising the same case from 17 to 42 cores gave a speed-up of 0.9786 — marginally slower — at 2.5× the core-hours, so the wider allocation was abandoned. The figure is specific to this problem size and is re-measured whenever the mesh tier changes.
